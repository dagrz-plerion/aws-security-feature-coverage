Known limits

Counts are a floor, not a ceiling. A page that names a service AWS spells differently from the reference data leaves that service uncounted rather than guessed at, so several features undercount. The faults behind that — a name hung on the wrong service, real services carrying no name at all, one resource listed under two ids — are written up in universe-defects.md, along with what each one costs. Two features derive Region coverage from stated exclusions rather than reading it directly; they are marked as derived, and their notes say what baseline they assume.

How to read this

Full means the page states the item is reached with nothing carved out. Partial means the item is reached but the page names a carve-out inside it — a Region where the service runs but some of its controls do not, or a resource type where only one sub-kind is protected. Excluded means the page states the item is not reached; excluded items are never added to a count. An item the page names but that matches no known Region, service or resource type is listed as unresolved and is never counted. Absence of a statement is never coverage.
